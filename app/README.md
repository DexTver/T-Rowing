# app

Веб-приложение (Spring Boot 3.5, JPA, Spring Security, Thymeleaf). Зависит от `seeding-engine`.
Фаза 1 дорожной карты ТЗ: каркас + схема БД + RBAC.

## Запуск

### Через Docker (рекомендуется) — поднимает PostgreSQL и приложение
```
docker compose up --build
```
Приложение: http://localhost:8080  ·  начальный вход: `admin` / `admin` (сменить!).
Демо-данные при пустой БД — `APP_SEED_DEMO=true` (compose читает из окружения). Создаёт демо-соревнование
(публичная часть и судейская) и демо-тренера **`trainer` / `trainer`** с открытой для регистрации категорией.

### Локально (нужен запущенный PostgreSQL)
```
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/trowing ./mvnw -pl app -am spring-boot:run
```

## Что есть в фазе 1

- **Схема БД** (Flyway `db/migration/V1__init.sql`) по разделу 5 ТЗ + многодневность:
  `competition_day` и привязка `category.competition_day_id`; сквозная нумерация заездов — `heat.number`.
  Галочки финалов B/C — `category.final_b_enabled` / `final_c_enabled` (метод `enabledFinals()` отдаёт
  множество для движка).
- **JPA-сущности** всех таблиц (пакет `domain`), **репозитории** (`repo`).
- **RBAC** (раздел 3): роли `TRAINER`/`JUDGE`/`ADMIN` (VIEWER — аноним), сессии, BCrypt,
  CSRF включён. `/admin/**`, `/judge/**`, `/trainer/**` — по ролям; публичная часть открыта.
- Начальный администратор создаётся при пустой БД (`AdminSeeder`).
- Заглушки страниц `/` и `/login`.

## Тесты и проверка схемы

- Тесты (`./mvnw -pl app -am test`) идут на **H2** (без Docker): проверяют запуск контекста,
  сидирование админа и сохранение многодневного соревнования с категорией.
- В реальном запуске на PostgreSQL `spring.jpa.hibernate.ddl-auto=validate` сверяет сущности
  со схемой Flyway (схемой владеет Flyway).

## Публичная часть (фаза 3, раздел 7.1)

- Главная `/` — список соревнований (LIVE наверху, далее по дате).
- Страница соревнования `/competitions/{id}` — описание + таблица заездов (№ сквозной, время, категория, этап).
  Протокол не виден до статуса `PROTOCOL_FORMED` (раздел 6).
- Заезд `/heats/{id}` — результаты: не пройден → по дорожке; пройден → по времени, `DNF/DNS/DSQ` в конце.
- Фильтры `/results` — по спортсмену/тренеру/категории/субъекту/спорт-школе. Для анонимов предусмотрен
  хук капчи (`CaptchaService`, по умолчанию выключена; провайдер подключается реализацией +
  `app.captcha.enabled=true`).

Время форматируется/парсится в одном месте — `util/TimeFormat`.
